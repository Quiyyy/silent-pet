## 招手如何触发

对本地 Codex 26.915.4065.0 静态代码核对：`first-awake` 问候映射到 `waving`，通知有效期约8秒，并按宠物ID记录已问候状态。因此同一宠物通常不会反复招手，切换回来也不保证再次触发。更高优先级状态、悬停或拖动可能覆盖它。普通悬停使用 `jumping`（本项目的亲近回应），不等于招手。

预览“招手”按钮可以随时循环查看四帧。客户端招手单轮时长为140/140/140/280ms；问候窗口和单轮时长不同。本项目没有改变宿主触发逻辑。

## 已知限制

内膝在移动第4/5帧压缩仍偏紧，有轻微蹲行感；正常尺寸未发现明显肢体畸变。宿主保留8帧、末帧220ms（其余120ms）的节奏，循环边界仍可能有较长停留。本轮未进行原生桌面实时输入验收，浏览器测试不代表宿主测试。

本地安装只替换图集，宠物ID和配置保留。桌面实例若缓存旧图，应切换其它宠物再选回，必要时完整退出并重开Codex。

## 可复现材料

当前母图、图层、提示词、未清理图集和归一化条带已保存。按照 [角色约束](character-spec.md) 编辑，不能恢复含鞋历史素材。

```bash
python tools/render_gait.py --output output/motion --walk-source source/rig/master.png --wave-source source/wave/master.png
python tools/test_gait.py --root output/motion
```

脚本生成移动与招手三行动作，其余状态使用当前 `source/preclean/spritesheet.png`。替换对应格后，在未清理图集上仅运行一次 hatch-pet 的边缘去色与最终验证。`tools/correct_standing_feet.py` 是历史含鞋图集的一次性修复工具，不应再次应用于已修正的裸足基线。

旧版文档和QA保留为历史证据，不代表本次当前素材。生成服务有随机性；确定性渲染可复现选定母图的动作，不能保证重新生成母图得到相同像素。
