# 用户视角审核与桌面支持核对 · 2026-10-15

本轮结论：上次的扭腿、额外手臂和招手牵动头角已不再是主要问题；下一轮应优先统一跨状态原画、补足移动身体跟随和视线过渡。当前客户端有完整v2视线渲染，但没有发现可由自定义宠物配置的“鼠标靠近、点击撒娇、时长或冷却”接口。

## 审核范围与可信边界

读取当前安装图集并确认它与仓库一致：`e9135f701500d2679322f8490999d5e4063b830db9ae63a8d771756d0b3ed9fe`。检查了全部九组动作的有序帧、16方向和默认姿态，并在内置浏览器里操作状态切换、播放规则、互动原型、键盘、任务优先及减少动态效果；以192×208图格和0.5倍小尺寸观察可读性。

本轮没有重绘或替换桌面图集，也没有修改客户端。桌面支持来自已安装程序的只读实现检查和官方文档；浏览器验证不等于原生桌面实时输入测试。部分自然度评价是用户体验判断，不是格式校验的“通过/失败”。

## 完整动画审核

| 动作 | 真实使用感受 | 后续优化重点 |
| --- | --- | --- |
| 待机 idle | 短直裸腿稳定、整体安静。真正桌面一轮为6.6秒，远慢于旧预览；第四帧半眯眼约停留0.84秒，偏放松。 | 保留克制感，不继续整体放慢；如更强调猎手警觉，可微调该帧眼睑，而非再次做大幅点头。 |
| 向右移动 | 没有旧版S形腿，但腿摆动很小，上半身几乎静止。小尺寸更像随拖动滑行。与待机的头发轮廓、卷轴角度和腿粗有换画感。 | 优先以同一关键姿态统一头脸和卷轴体积；增加极小的肩/身体重心跟随与披风滞后，保持整腿短直。 |
| 向左移动 | 镜像方向正确，交替可辨；同样有上身静止感。左右即时切换仍是整幅翻面。 | 与向右一起调整，先处理换向接续，不重新引入复杂膝踝变形。 |
| 招手 | 头角/头骨稳定、两臂两手正确；现在的手掌摆动在小尺寸偏弱，看起来接近举手定格。 | 在现有独立手掌范围内增加清楚但克制的摆幅，保持手腕连接；不要扩大到角或头发。 |
| 亲近 jumping | 半眯眼微笑舒缓，但与待机表情相近，某些入场姿态下反馈偏弱。 | 增加轻微“注意到你”的眼睑/嘴角区别，保持首尾可接回待机，避免三轮快速眨眼或点头。 |
| 失落 failed | 低头和表情变化可辨，未见需要再重做的解剖问题。 | 低优先级，保持当前克制反应；持续错误状态应由宿主提示承载。 |
| 等待 waiting | 伸手请求回应较清楚，比纯眼神变化更易识别。 | 保留；统一伸手后回收的关键姿态和手/卷轴关系。 |
| 工作 running | 读卷轴主题适合角色，但正常尺寸下与待机差异很小。 | 可用原有手指沿卷轴轻移、视线跟读，突出“正在处理”；避免新增第三只手。 |
| 完成 review | 微笑、抬眼很克制，但容易与工作/待机混淆。 | 做一次明确的小幅抬眼或轻点头，并平稳收回；完成结果仍以宿主活动提示为准。 |
| 16方向 | 四主方向可辨、腿部保持稳定；157.5→180、337.5→000→22.5等区间头部俯仰/转向变化比其它区间明显。 | 优先缩小这几段的姿态差，保持头脸体积与卷轴锚点；不要用整张图倾斜伪造视线。 |

整体角色已经可用，优先级是动画一致性和辨识度，不适合再进行全量风格重绘。放大检查还发现44个格含少量独立alpha碎点，示例多为1–2像素，集中在下肢/边缘附近；小尺寸影响有限，属于后续精修项，不是新的腿断裂或去色失败。

建议顺序：

1. P1：统一待机/移动/招手/亲近的头脸与卷轴关键姿态，减少换画感。
2. P1：在短直腿基础上补极轻身体与披风跟随；同时柔化视线跨段接续。
3. P2：提高招手、亲近、工作和完成的动作辨识度，按桌面三轮规则设计首尾。
4. P3：清理独立边缘碎点，并在小尺寸验收；不要重复执行色边清理破坏已通过的图集。

## Codex 是否更新了支持

本机运行版本工具报告 `26.1002.52244`，build `13536`；Windows安装包为 `26.1002.7124.0`。上次检查的安装包为 `26.915.4065.0`，客户端确实已更新。更新检查接口返回 `unavailable / disabled for build flavor (prod)`，因此不能据此断言没有更新可装或已经是最新版本。

[官方Pets文档](https://learn.chatgpt.com/docs/pets?surface=app)确认：桌面支持宠物大小和重置、悬浮Quick Chat、任务活动托盘及系统减少动态效果；自定义桌面宠物保存在本地，不自动同步到Web。相关公开变更见[2026-09-11更新记录](https://learn.chatgpt.com/docs/changelog#codex-2026-09-11-app)，它早于上次制作日期，不能当作本轮新开放的能力。本次未找到9月20日之后发布自定义宠物交互API的官方公告。

| 能力 | 当前核对结果 | 对猎豹的意义 |
| --- | --- | --- |
| v2 / 16方向 | 仍支持1536×2288、9状态+16方向；当前图集已兼容。 | 无需再升级图集版本。 |

| 悬停亲近 | 原生入口立即切到jumping；默认三轮后慢速待机，离开或更高优先级瞬时状态会改变播放。 | 图集能改变反应画面，不能添加500ms停留门槛或4秒冷却。 |
| 单击宠物 | 由宿主操作处理；未发现自定义“点击撒娇”回调或独立可配置动作槽。 | 浏览器原型的点击回应不能随图集安装进桌面。 |
| 自定义帧时长/重复次数 | 本地manifest读取字段仍为id、displayName、description、spriteVersionNumber、spritesheetPath。当前renderer增加内部loop选项，但桌面mascot没有传入，它也不是manifest字段。 | 不应添加无效的fps、cooldown、onClick等字段。 |

## 本轮已落实的交互与预览修正

旧预览把“基础帧时长”当成完整桌面规则，导致待机被显示为1.1秒无限循环。只读对比发现：26.915和26.1002都将待机时长乘6；非idle动作默认重复三次，再回到慢速idle。这是旧预览遗漏的规则，并非本次客户端更新才增加。

现在预览分为：

- **桌面播放规则模拟**：待机6.6秒一轮，其它动作三轮后回到慢速待机，同时保留请求的任务状态，避免误以为任务完成。
- **逐帧循环检查**：按基础帧时长持续循环，便于找接缝、抽搐和比例变化；手动逐帧会明确切入此模式。
- **互动设计原型**：保留靠近注视、点击/悬停单次2.4秒回应、4秒冷却和任务优先；待机改为6.6秒。页面明确这些交互不能直接安装到桌面。

帧格192×208的说明改为“图格原始尺寸”，不再声称等于用户的桌面显示尺寸。另为脚本增加版本查询，解决浏览器重载后仍使用旧交互脚本的实际缓存问题。

按默认非覆盖分支，亲近三轮为2.52秒、招手三轮为2.1秒、单向移动三轮为3.18秒；拖动、视线或状态变更可能重置/覆盖实际播放。同向长拖动是否会在真实宿主持续进入待机还需桌面实测，不把模拟结果当作已验证的原生行为。
